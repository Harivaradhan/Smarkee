API Contract for SMARKEE Frontend

1) Authentication

POST /auth/login
Request JSON:
{
  "username": "string",
  "password": "string",
  "role": "Admin|Manufacturer|Distributor|User"
}

Successful Response JSON (frontend accepts either shape):
Option A:
{
  "token": "jwt-or-session-token",
  "user": {
    "id": "string|number",    // optional but helpful
    "username": "string",
    "fullName": "string",
    "role": "Admin|Manufacturer|Distributor|User",
    "email": "string (optional)",
    "phone": "string (optional)"
  }
}

Option B (alternate keys):
{
  "accessToken": "jwt-or-session-token",
  "user": { /* same user object as above */ }
}

Notes:
- Frontend code (AuthProvider) will accept response.token OR response.accessToken and response.user OR the whole response as user if shaped differently.
- If you provide only a token and then an endpoint to fetch the user (`GET /auth/me`), that's fine.

GET /auth/me
Response:
{
  "id": "string|number",
  "username": "string",
  "fullName": "string",
  "role": "Admin|Manufacturer|Distributor|User",
  "email": "string",
  "phone": "string"
}

POST /auth/register
Request:
{
  "company"?: "string",
  "username": "string",
  "password": "string",
  "email": "string",
  "role": "string",
  /* additional registration fields as required */
}

Response: standard 201 created with created user object or success message.

6) General notes & conventions
- Timestamps: use ISO 8601 (e.g. "2026-07-28T10:30:00Z") or the human-friendly format used in the demo data (frontend displays raw strings).
- Numeric values: where frontend expects numbers (counts, quantities), send numbers (not strings). UI demo files may contain formatted strings (e.g., "2,450" for display) — backend should return raw numbers and frontend can format them.
- Localization: dates/times may be localized on the frontend — returning ISO strings is safest.
- Pagination & filters: for large lists (bins, notifications, people), prefer supporting query params: `?page=1&pageSize=50`, `?city=...`, `?status=...`.
- Errors: use standard HTTP status codes and JSON error body: `{ "error": "message", "details": {...} }`.
